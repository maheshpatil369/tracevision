# API Reference

Interactive, always-current documentation is auto-generated by FastAPI at
`http://localhost:8000/docs` (Swagger UI) and `/redoc`. This file is a
human-readable summary of the same routes for quick reference; the live
`/docs` endpoint is authoritative if the two ever disagree.

All endpoints are unauthenticated in this build (spec section 33 makes auth
"if implemented"; `users`/hashing scaffolding exists in `app/models/user.py`
and `requirements.txt` but no login endpoint is wired up — see
`docs/security.md` and `docs/limitations.md`). Every response is
`{"success": true, "data": ...}` on success or
`{"success": false, "error": {"code", "message"}}` on failure
(spec section 71).

## Cases
| Method | Path | Purpose |
|---|---|---|
| POST | `/api/cases` | Create a case. Body: `{case_number, title, description?, analyst_id?, notes?}` |
| GET | `/api/cases?page=&page_size=&status=` | Paginated list, optional status filter |
| GET | `/api/cases/{case_id}` | Get one case |
| PATCH | `/api/cases/{case_id}` | Partial update: `{title?, description?, status?, notes?, analyst_id?}` |
| POST | `/api/cases/{case_id}/archive` | Shortcut for `status=archived` |
| DELETE | `/api/cases/{case_id}` | Delete a case (cascades to its videos/reports) |

Validation: `case_number` must match `^[A-Za-z0-9._-]{3,50}$` and be unique
(`DUPLICATE_CASE_NUMBER` / `INVALID_CASE_NUMBER` error codes). `status` must
be one of `open`/`in_progress`/`closed`/`archived` (`INVALID_CASE_STATUS`).

## Videos
| Method | Path | Purpose |
|---|---|---|
| POST | `/api/videos/upload?case_id=` | Multipart upload (`file`). Validates extension/size/decodability, extracts real metadata |
| GET | `/api/videos/{video_id}` | Get one video's metadata |
| GET | `/api/videos/by-case/{case_id}` | List videos for a case |
| DELETE | `/api/videos/{video_id}` | Delete video + its file on disk |

Errors: `UNSUPPORTED_FORMAT`, `EMPTY_FILE`, `FILE_TOO_LARGE`,
`UNREADABLE_VIDEO`, `NO_READABLE_FRAMES` (all 4xx, never a raw exception).

## Analyses
| Method | Path | Purpose |
|---|---|---|
| POST | `/api/analyses?video_id=` | Create + immediately queue an analysis. Body (optional): `AnalysisSettings {detection_confidence, iou_threshold, frame_interval, tracker}` |
| GET | `/api/analyses/{analysis_id}` | Get one analysis |
| GET | `/api/analyses/{analysis_id}/status` | `{analysis, job}` — poll this for real progress |
| GET | `/api/analyses/by-video/{video_id}` | List analyses for a video |
| POST | `/api/analyses/{analysis_id}/cancel` | Cancel a queued/processing analysis |

## Forensic data (read-only, all scoped to one analysis)
| Method | Path | Purpose |
|---|---|---|
| GET | `/api/objects/by-analysis/{analysis_id}` | Object-class summary table |
| GET | `/api/tracks/by-analysis/{analysis_id}` | Tracked objects with trajectories |
| GET | `/api/faces/by-analysis/{analysis_id}?include_landmarks=` | Faces + geometric features (landmarks omitted by default — large payload) |
| GET | `/api/evidence/by-analysis/{analysis_id}` | Evidence frames |
| GET | `/api/timeline/by-analysis/{analysis_id}` | Chronological timeline |

## Reports
| Method | Path | Purpose |
|---|---|---|
| POST | `/api/reports` | Generate a PDF. Body: `{analysis_id, demo_mode?}` |
| GET | `/api/reports/by-case/{case_id}` | List reports for a case |
| GET | `/api/reports/{report_id}` | Report metadata |
| GET | `/api/reports/{report_id}/download` | Streams the PDF file (`409 REPORT_NOT_READY` if not completed) |

## Models
| Method | Path | Purpose |
|---|---|---|
| POST | `/api/models/train` | Train a classifier. Body: `{algorithm, cv_folds, search, dataset_description, samples: [{feature_vector, label}]}` |
| GET | `/api/models` | List trained model versions + real metrics |
| POST | `/api/models/compare` | Compare a face against a reference/classifier. Body: `{face_id, reference_face_id?, reference_label?, analyst_notes?}` |

## Example: full happy-path request sequence

```bash
# 1. Create a case
curl -X POST localhost:8000/api/cases -H 'Content-Type: application/json' \
  -d '{"case_number":"CASE-2026-001","title":"Parking lot incident"}'

# 2. Upload a video
curl -X POST 'localhost:8000/api/videos/upload?case_id=<case_id>' -F file=@clip.mp4

# 3. Start analysis
curl -X POST 'localhost:8000/api/analyses?video_id=<video_id>'

# 4. Poll status
curl localhost:8000/api/analyses/<analysis_id>/status

# 5. Once completed, generate a report
curl -X POST localhost:8000/api/reports -H 'Content-Type: application/json' \
  -d '{"analysis_id":"<analysis_id>"}'

# 6. Download it
curl -OJ localhost:8000/api/reports/<report_id>/download
```
